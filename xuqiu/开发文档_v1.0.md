```cmake
idf_component_register(
    SRCS

        "w25q128.c"
        "wifi_prov.c"
        "ai_client.c"
        "battery.c"
    INCLUDE_DIRS "."
    REQUIRES
        driver
        esp_driver_gpio esp_driver_spi esp_driver_i2c
        esp_driver_i2s esp_driver_dma esp_driver_adc
        esp_wifi esp_event esp_netif nvs_flash
        esp_http_server esp_http_client json
        littlefs fatfs tinyusb esp-sr
        oled font_service wifi_manager app_log

```

## 三、已核对到的组件缺陷（开发时必须规避）

> 本节记录读取组件头文件后确认的真实问题，**不是猜测**。
> `COMPONENTS.md` 已警告部分组件「README 写的函数在头文件中并不存在」。

### 3.1 `oled` 组件的引脚冲突（阻塞项）

`d:\components\oled\include\oled.h` 把引脚**硬编码在头文件里**：

```c
#define OLED_SDA_PIN        GPIO_NUM_6  /* SDA -> GPIO 6 */
#define OLED_SCL_PIN        GPIO_NUM_5  /* SCK -> GPIO 5 */
```

而本项目 **GPIO6 是 ESP32-S3 内部 Flash 脚**、**GPIO5 已被 0.96" 屏的 CS 占用**。

**后果**：直接使用会导致 0.91" 屏初始化失败或破坏 Flash 读写。

**解决方案（三选一）**：

| 方案 | 做法 | 评价 |
| --- | --- | --- |
| A. 改组件头文件 | 把 `OLED_SDA_PIN` / `OLED_SCL_PIN` 改成本项目实际引脚 | 最简单，但改动共享组件影响其他项目 |
| B. 改组件为参数注入 | 新增 `oled_init_with_pins(sda, scl, addr)`，保留原 `oled_init()` 兼容 | 最规范，需改组件源码 |
| C. 封装适配层 | 在 `main/oled_i2c.c` 里另写 I2C 初始化，绕开组件的 `oled_init()` | 隔离性最好，但重复实现 |

**建议**：方案 B。理由——本项目已确立「引脚参数注入」规范，组件也应遵循；
且 `d:\components` 是共享代码库，方案 A 会污染其他项目。

### 3.2 `font_service` 的显示回调不匹配 0.96" 单色屏

`font_service.h` 的回调签名是 **RGB565** 语义：

```c
typedef void (*lcd_set_window_t)(uint16_t x, uint16_t y, uint16_t w, uint16_t h);
typedef void (*lcd_write_data16_t)(uint16_t data);
```

`write_data16` 接收 `uint16_t` 颜色值（RGB565）。而 SSD1306 是**单色屏**，
数据是 `uint8_t` 页格式，**没有颜色概念**。

**解决方案**：在 `font/font_render.c` 里做适配——
`write_data16(uint16_t data)` 只取 `data` 的低位判黑白：
非 0 → 点亮像素（1），0 → 熄灭（0），并把 `uint16_t` 拆成 2 个 `uint8_t` 写入。

**注意**：SSD1306 是页寻址，`set_window` 回调需要正确设置页范围与列地址，
不能用适配 LCD RGB 接口的思路直接套。

### 3.3 `oled` 组件的字符绘制与 `font` 组件不兼容

`COMPONENTS.md` 已记录：`oled_draw_char/string` 的 `font_data` 是**整表基址**，
与 `font_service` 的 `get_font()` 返回的单字字模**格式不同**，混用会花屏。

**结论**：0.91" 屏（WiFi 图标/状态）用 `oled_draw_*` + `font` 组件；
0.96" 屏（中文显示）用 `font_service` + `font_render` 适配层。**两条渲染路径不要混用。**

### 3.4 `wifi_manager` 的 API 陷阱

- `wifi_connect()` **没有参数**，用组件内部已保存的配置。
  连接指定 WiFi 需先 `wifi_config_save()` 再 `wifi_connect()`。
- README 提到的 `wifi_reconnect()` / `wifi_config_exists()` **在头文件中不存在**，不要调用。
- `wifi_scan_get_ap_results()` 扫描未完成时返回 `ESP_ERR_NOT_FINISHED`，需轮询重试。

### 3.5 `w25qxx_driver` 未编译的文件

`msc_disk.c` 未被 `SRCS` 引用，USB MSC 功能不可用，需手动加入。
若第九阶段用官方 `tinyusb` 实现 MSC，可不使用该组件。

## 四、开发规范（与全局规则一致）

### 4.1 代码组织

1. **一个设备一对独立 `.c`/`.h`**，文件名小写下划线并体现设备名。
2. **引脚通过结构体参数注入**：设备 `.h` 定义 `xxx_pins_t`，
   `init` 接收该结构体指针，驱动内**禁止硬编码 `GPIO_NUM_x`**。
3. **`main.c` 只做装配调度**，不含引脚宏与外设细节。
4. **不使用 JSON / 运行时配置承载编译期常量**。

### 4.2 变更备注规范

每个函数、每个结构体、每个文件头部必须写 `功能：` + `修改：YYYY-MM-DD ...`，
**同一天的多次修改汇总成一条**。

```c
/**
 * @brief  初始化 WiFi 配网子系统
 *
 * 功能：注册事件回调、按 NVS 配置决定进入 STA 或 SoftAP 模式
 * 修改：2026-10-03 新建
 */
esp_err_t wifi_prov_init(void);
```

### 4.3 ESP-IDF v6.1 注意事项

- 外设公开头**不再传递包含 FreeRTOS 头**。用到 `vTaskDelay` / `pdMS_TO_TICKS` /
  `xTaskCreate` 时必须显式 `#include "freertos/FreeRTOS.h"` 与 `"freertos/task.h"`。
- I2S API 在 v6.1 破坏性变更（`i2s_new_channel`、`sample_rate_hz`、`mclk_multiple` 等），
  详见 `main/max98357.c` 实现与全局规则对照表。
- 项目开启 `-Wall -Werror`，**字段名写错直接编译失败**。写外设代码前先读真实头文件，
  不要凭记忆写。

### 4.4 编译环境注意事项

PowerShell 中 `export.ps1` 会因 `IDF_TOOLS_PATH` 指向错误位置而失败。构建前设置：

```powershell
$env:PYTHONUTF8 = "1"
$env:ESP_IDF_VERSION = "6.1"
$env:IDF_VERSION = "6.1.0"
$env:IDF_TOOLS_PATH = "C:\esp\v6.1-rc1\tools"
$env:IDF_PATH = "C:\esp\v6.1-rc1\esp-idf"
$env:ESP_ROM_ELF_DIR = "C:\esp\v6.1-rc1\tools\esp-rom-elfs\20241011\"
$env:PATH = "C:\esp\v6.1-rc1\tools\python\v6.1-rc1\venv\Scripts;" +
            "C:\esp\v6.1-rc1\tools\cmake\4.0.3\bin;" +
            "C:\esp\v6.1-rc1\tools\ninja\1.12.1;" +
            "C:\esp\v6.1-rc1\tools\xtensa-esp-elf\esp-15.2.0_20251204\xtensa-esp-elf\bin;" +
            $env:PATH
idf.py build
```

> `ESP_IDF_VERSION` **不能带 `v` 前缀**，否则报 `Version string lacks a numerical component`。

## 五、分阶段实施计划

### 阶段 2：扩分区表（建议最先做）

**问题**：当前 `CONFIG_PARTITION_TABLE_SINGLE_APP=y`，app 分区仅 1 MB（`0x100000`），
现有固件 237 KB。中文字库需 752 KB，加入后约 989 KB，**必然溢出**。

**做法**：新建 `partitions.csv`，改为 `CONFIG_PARTITION_TABLE_CUSTOM`。

```csv
# Name,   Type, SubType, Offset,   Size,  Flags
nvs,      data, nvs,     0x9000,   0x5000,
otadata,  data, ota,     0xe000,   0x2000,
app0,     app,  ota_0,   0x10000,  0x200000,
app1,     app,  ota_1,   0x210000, 0x200000,
spiffs,   data, spiffs,  0x410000, 0x20000,
```

配套 `sdkconfig`：

```
CONFIG_PARTITION_TABLE_CUSTOM=y
CONFIG_PARTITION_TABLE_CUSTOM_FILENAME="partitions.csv"
CONFIG_PARTITION_TABLE_OFFSET=0x8000
```

**验收**：改完后 `idf.py build` 输出的 app 分区大小应大于字库需求。

### 阶段 3：0.91" I2C OLED

1. 先按 §3.1 方案 B 把 `oled` 组件改为参数注入
2. 新建 `main/oled_i2c.c`，构造 `oled_i2c_pins_t` 后调用组件接口
3. 显示 WiFi 图标与连接状态（图标字模用 `font` 组件，勿与 `font_service` 混用）

**引脚待定**：本项目尚未为 0.91" 屏分配 I2C 引脚。需避开已占用脚
（3/4/5/10/13/18/19/20/39/40/41/42）与 PSRAM（35~37）、内部 Flash（6/7）。

**验收**：上电后 0.91" 屏显示图标，点亮/熄灭状态随 WiFi 变化。

### 阶段 4：WiFi 配网

新建 `main/wifi_prov.c`，实现需求文档第四章的状态机。

关键实现点：

| 要点 | 实现 |
| --- | --- |
| 成功判据 | `IP_EVENT_STA_GOT_IP`，**不能**用收到 SSID/密码判据 |
| 顺序 | 先停 HTTP 服务再停 SoftAP，避免驱动状态错乱 |
| 失败重试 | ≥5 次进入 SoftAP；配网阶段连接失败**回配网页面不关 SoftAP** |
| 持久化 | `wifi_config_save()` 写 NVS |
| DNS 拦截 | 官方 `esp_http_server` + DNS 劫持返回 302 |

**依赖**：`wifi_manager` 提供 SoftAP/STA/扫描/NVS；HTTP 页面用官方 `esp_http_server`
自建（`d:\components\http_server` 虽有现成页面模块，但注意其 README 陷阱）。

**验收**：上电无配置时手机连上热点能弹出配网页面，提交后能连上并显示 IP。

### 阶段 5：中文字库接入 + 滚动显示

1. 按 §3.2 写 `font/font_render.c` 适配层，把 `oled_spi` 包装成 `FontLcdOps`
2. Kconfig 配置 GB2312 + 黑体：

```
CONFIG_FONT_SERVICE_ENABLE=y
CONFIG_FONT_SERVICE_DEFAULT_FONT_GB2312=y
CONFIG_FONT_SERVICE_ENABLE_GB2312=y
CONFIG_FONT_SERVICE_GB2312_FONT_HEI=y
CONFIG_FONT_SERVICE_ENABLE_BUILTIN=y
```

3. `ui.c` 实现滚动：128×64 屏每行 8 字、一屏 4 行 = **32 字**，
   超长文本按字节偏移滚动，建议 200ms 步进、行末停 1 秒

**验收**：中文正常显示不花屏；长文本能滚动；刷新无闪烁。

### 阶段 6：AI 对话链路

新建 `main/ai_client.c`。

| 项目 | 实现 |
| --- | --- |
| HTTP | 官方 `esp_http_client` |
| JSON | 官方 `cJSON` |
| 超时 | 10~15 秒，重试 1 次 |
| 上下文 | 滑动窗口，保留最近 6~10 轮 |
| 错误分类 | 区分「网络不通」与「API 返回错误」，分别反馈 |

**API Key 处理**：烧录时写入加密 NVS 分区，运行时读取拼装 Header。
**严禁**硬编码进固件、写入日志文件、提交仓库。

**验收**：能成功请求一次 AI 并显示回答；断网时给出正确提示。

### 阶段 7：STT / TTS 接入（**当前阻塞**）

需求文档第十节列的 P0 待确认项未解决前无法开工。需先确定供应商。

### 阶段 8：电源管理

新建 `main/battery.c`，用官方 `esp_adc`（建议 ADC oneshot 模式）采样电阻分压。

| 阈值 | 处理 |
| --- | --- |
| < 3.3V | 语音提示「电量不足」 |
| < 3.0V | 关闭 WiFi/AI，保留基础显示或关机保护 |
| 充电中 | OLED 显示「正在充电」 |

**验收**：低电压时行为符合需求文档表格。

### 阶段 9：W25Q128 双分区 + USB MSC

| 子任务 | 选型 |
| --- | --- |
| FATFS 挂载 | 官方 `fatfs` |
| LittleFS 挂载 | 官方 `littlefs`，启用 lookahead + `block_cycles≈512` |
| USB MSC | 官方 `tinyusb` |

流程按需求文档 7.3：暂停 AI 写入 → 复制日志到 FAT32 → 注册 MSC → 拔出恢复。

**关键约束**：导出期间**必须暂停 AI 日志写入**，否则 FAT 分区易损坏。

## 七、风险与注意事项

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| app 分区溢出 | 字库放不下，构建失败 | 阶段 2 先扩分区 |
| `oled` 组件引脚与 Flash 冲突 | 0.91" 屏失败或破坏 Flash | §3.1 方案 B 改为参数注入 |
| `font_service` RGB 回调不匹配单色屏 | 中文花屏 | §3.2 写适配层 |
| 两条渲染路径混用 | 花屏 | 0.91" 用 `font`，0.96" 用 `font_service` |
| 0.96" CS 浮空 | 屏初始化随机失败 | **硬件加 10K 上拉电阻** |
| 凭据泄露 | 账号被盗用 | 加密 NVS；发现暴露立即轮换 |
| 电源环境乱码 | `git` 命令不可用 | 见下方环境问题 |

### 7.1 环境问题记录

ESP-IDF 输出通道日志中的 `SYSTEM_PATH` 存在乱码：

```
C:\Program Files (x86)\税务证书应用客户?C:\Progr;m Files\Git\cmd
```

中文目录名按非 UTF-8 编码写入导致 `\Git\cmd` 丢失，`git` 命令将不可用。
若构建报 git 相关错误，先处理此环境变量。
