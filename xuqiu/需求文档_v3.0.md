## 一、产品概述

基于 ESP32-S3 的智能语音对话终端，具备：

- WiFi 自动配网（SoftAP + Captive Portal）
- 离线语音唤醒（唤醒词「小乐同学」）
- AI 文本问答（天翼云 EAI，OpenAI 兼容协议）
- 双屏显示（0.91" I2C + 0.96" SPI）
- W25Q128 日志存储（LittleFS + FAT32 双分区）
- USB 文件访问（TinyUSB MSC 虚拟 U 盘）

工作流程：上电 → 读取 NVS 中的 WiFi 配置 → 连接成功后进入 AI 待机模式 →
语音唤醒 → STT 转文本 → 请求 AI → 接收回答 → TTS 播报 + 0.96" 屏滚动显示 →
对话记录写入 W25Q128。

### 2.1 对 v2.1 的硬件修正（重要）

| 项目 | v2.1 原文 | v3.0 结论 | 原因 |
| --- | --- | --- | --- |
| 功放 | PAM8403 | **MAX98357** | PAM8403 是**模拟输入**，需额外一颗 I2S→DAC；MAX98357 直接吃 I2S，省掉 DAC 且固件零额外驱动 |
| Flash | W25Q128（16MB） | **W25Q128（16MB）** | 确认与代码一致；此前代码误按 W25Q32（4MB）实现，已修正 |
| 麦克风 | 麦克风 + 前置放大（泛指） | **INMP441**（I2S 数字输出） | 数字麦克风自带前置放大与 ADC，**不需要单独的模拟前置放大电路**；输出可直接进 ESP32 的 I2S 控制器 |

### 2.1.1 音频链路说明（INMP441 + MAX98357）

```
                    ┌──────────────┐
   INMP441 ────────▶│ESP32-S3│───────▶ MAX98357 ──▶ 喇叭
   (I2S 输入)        │  I2S 控制器 │        (I2S 输出)
   SCK/WS/SD  ◀──────│            │──────▶ BCLK/LRC/DIN
                    └──────────────┘
```

| 芯片 | 接口 | 关键点 |
| --- | --- | --- |
| INMP441 | I2S 数字输入 | 24-bit 输出；WS 脚**必须接高电平**（左声道）或接地（右声道），悬空会有噪声；SD 脚输出数据需 MCU 上拉 |
| MAX98357 | I2S 数字输出 | SD_MODE 脚决定左右声道与增益 |

**关键约束**：
- 麦克风与功放共用 `I2S_NUM_0` 的 BCLK(18) / LRC(19)，仅数据线分离：
  功放 DIN = GPIO20，麦克风 SD = 待定（建议 GPIO41，但已被 Flash MOSI 占用，需另选）
- 若改用独立 I2S 端口（`I2S_NUM_1`），则麦克风独占一组 BCLK/LRCLK/SD 引脚，
  避免与功放争抢同一时隙，工程上更清晰
- 唤醒词检测（ESP-SR）可直接消费 I2S 采集的 PCM 数据，无需中间文件

### 2.2 引脚分配（已确认，见 `main/main.c`）

**OLED 0.96"（SSD1306，SPI2_HOST）**

| 信号 | GPIO | 说明 |
| --- | --- | --- |
| SCK | 13 | 避开 GPIO6（内部 Flash） |
| MOSI | 10 | 避开 GPIO7（0.91" 屏的 SDA） |
| CS | 5 | strap 脚，**必须外接 10K 上拉到 3.3V** |
| DC | 3 | strap 脚 |
| RST | 4 | strap 脚 |

**MAX98357（I2S_NUM_0，输出）**

| 信号 | GPIO | 说明 |
| --- | --- | --- |
| BCLK | 18 | 与 INMP441 共用 |
| LRC | 19 | 与 INMP441 共用 |
| DIN | 20 | 避开 PSRAM 占用的 GPIO35~37 |

**INMP441（I2S_NUM_0，接收）—— 引脚待确认**

| 信号 | GPIO | 说明 |
| --- | --- | --- |
| SCK | 18（共用 BCLK） | 与 MAX98357 共用 |
| WS | 19（共用 LRC） | **硬件必须接高电平（选左声道）或接地（选右声道），悬空有噪声** |
| SD | **待定** | INMP441 数据输出，**建议 GPIO47 或 GPIO48** |
| VDD | 3.3V | |
| GND | GND | 与 ESP32 共地 |

> **引脚占用现状**：3/4/5（OLED）、10/13（OLED SPI）、18/19/20（I2S）、
> 39~42（Flash SPI3）、43/44（USB Console）、35~37（PSRAM）。
> 剩余可选：**GPIO47、GPIO48**（GPIO45/46 为仅输入，不适合 I2S 数据）。

**W25Q128（SPI3_HOST）**

| 信号 | GPIO | 说明 |
| --- | --- | --- |
| CS | 39 | SPI3 固定映射 |
| SCK | 40 | |
| MOSI | 41 | |
| MISO | 42 | |

> **注意**：GPIO3/4/5 是 strap 脚，上电采样前需保持高阻。
> **注意**：0.96" 屏 CS 必须外接上拉电阻，否则复位到 `spi_bus_add_device()` 之间 CS 浮空。

### 2.3 SPI 分配决策

0.96" 屏与 W25Q128 **使用独立的 SPI2 / SPI3 控制器，不共用总线**。

- 决策日期：2026-10-03
- 理由：共用总线时两个设备片选切换存在"短暂双选中"窗口，会导致 MISO 总线冲突；
  分用控制器可完全规避此问题，且 ESP32-S3 有 3 个 SPI 控制器，资源充足。
- 不引入 74HC595 做片选扩展：当前仅 2 个 SPI 设备，且访问天然串行，收益不足。

## 三、代码组织规范（已确认，见全局规则）

```
main/
├── main.c              # 板级装配层：持有全部引脚定义，依次初始化各设备
├── oled_spi.c/.h       # 0.96" OLED 驱动，init 接收 oled_spi_pins_t
├── max98357.c/.h       # 功放驱动，init 接收 max98357_pins_t
├── w25q128.c/.h        # Flash 驱动，init 接收 w25q128_pins_t
└── CMakeLists.txt
```

规范要点：

1. **一个设备一对独立 `.c`/`.h`**，文件名小写下划线并体现设备名。
2. **引脚通过结构体参数注入**：设备 `.h` 定义 `xxx_pins_t`，`init` 接收该结构体指针，
   驱动内**禁止硬编码 `GPIO_NUM_x`**，实际引脚值写在 `board.c`（板级装配层）。
3. **`main.c` 保持极简（不超过 20 行）**：只做串行调用
   （`board_log_pinout()` → `board_init_devices()` → `app_wifi_init()`），
   任何初始化、事件回调、状态查询逻辑都下沉到专属文件。
4. **每个文件的函数头必须写变更备注**：`功能：...` + `修改：YYYY-MM-DD ...`，
   同一天的多次修改**汇总成一条**。
5. **不使用 JSON / 运行时配置承载编译期常量**。
6. 新增 `.c` 后必须同步更新 `CMakeLists.txt` 的 `SRCS`。

### 3.1 文件分工

```
main.c          装配入口：仅串行调用，全文不超过 20 行
board.c/.h      板级：引脚定义 + 引脚表打印 + 设备初始化
app_wifi.c/.h   业务层：配网事件回调 + 状态查询（未来接 UI / TTS）
wifi_prov.c/.h  配网底层：NVS + 状态机 + 事件派发（封装 wifi_manager）
xxx.c/.h        设备驱动：单一外设的完整实现
```

判定标准：某段逻辑若与**具体设备**有关 → 放设备文件；
若与**具体业务**有关 → 放 `app_*.c`；
若与**本板硬件接线**有关 → 放 `board.c`；
只有跨三者的串行调度才留在 `main.c`。

## 四、WiFi 配网

### 4.1 状态机

| 触发条件 | 设备状态 | 执行动作 |
| --- | --- | --- |
| 上电启动 | 无保存 WiFi 配置 | 启动 SoftAP，进入配网模式 |
| 上电启动 | 已有保存 WiFi 配置 | 以 STA 模式连接目标 WiFi |
| STA 连接失败 ≥5 次 | 已有配置但连接失败 | 停止当前连接，进入 SoftAP 配网模式 |
| 手机提交 SSID/密码 | SoftAP 配网中 | 保存配置到 NVS，切换 STA 模式连接 |
| STA 获取到 IP | 配网阶段 | 关闭 SoftAP，仅保留 STA 模式 |
| STA 连接失败 | 配网阶段 | **重新回到 SoftAP 配网页面** |
| 配网超时 | SoftAP 配网中 | 保持 SoftAP，等待重新提交 |

### 4.2 配网交互

启动 SoftAP，SSID 固定（如 `XIAOLE_WIFI`），密码可固定或随机生成；内置 DNS 拦截 +
HTTP 服务器，手机连上热点后弹出 Captive Portal 配网页面，提供附近 WiFi 列表、
手动输入 SSID/密码、连接状态轮询。

- 0.91 寸屏以手机样式显示 WiFi 图标并播报连接结果
- 配网成功后 0.96 寸屏显示「WiFi 已配置 / WiFi 已连接 / IP 地址」
- 扩音器依次播报「WiFi 已配置」「WiFi 已连接」

### 4.3 配网成功后的处理顺序

1. 将 SSID、密码写入 NVS 持久化
2. 停止配网页面服务
3. 停止 SoftAP
4. WiFi 切换为纯 STA 模式
5. 0.96 寸屏显示「WiFi 已配置」「WiFi 已连接」
6. 扩音器播报「WiFi 已配置」「WiFi 已连接」
7. 进入 AI 待机模式等待唤醒

### 4.4 实现要点

- 配网成功判断标准为 **STA 获取到 IP（`IP_EVENT_STA_GOT_IP`）**，不能仅凭收到 SSID/密码
- 关闭 SoftAP 前**先停止 HTTP 配网服务**再切换 WiFi 模式，避免驱动状态错乱
- 新保存的 WiFi 连接失败时**不得关闭 SoftAP**，应回到配网页面避免失联
- 正常上电优先从 NVS 读取配置直接进入 STA 流程，不再自动开 SoftAP

### 4.5 组件选型

按「官方组件优先 → `d:\components` 自定义组件 → 自建」的顺序：

- `d:\components\wifi_manager`：覆盖 SoftAP、STA、扫描、SNTP、SoftAP 配网、Web 配网
- 注意该组件已知陷阱：README 提到的 `wifi_reconnect()` / `wifi_config_exists()`
  在头文件中并不存在，使用前以头文件为准

## 五、中文字库方案（已确认）

**选型：`font_service` + GB2312 子集 + 黑体（Hei），只链接一种字体。**

| 项目 | 结论 |
| --- | --- |
| 组件 | `d:\components\font_service` |
| 字库 | GB2312（6763 常用汉字） |
| 字形 | 黑体 Hei（小字号下笔画最清晰，OLED 可读性最好） |
| 点阵格式 | 16×16 column-lsb，SSD1306 page layout |
| 体积 | 字库 710 KB + Unicode→GBK 映射表 42 KB ≈ 752 KB |
| 依赖 | 不依赖 LVGL，通过注入写像素回调驱动裸驱 |

Kconfig 配置：

```
CONFIG_FONT_SERVICE_ENABLE=y
CONFIG_FONT_SERVICE_DEFAULT_FONT_GB2312=y
CONFIG_FONT_SERVICE_ENABLE_GB2312=y
CONFIG_FONT_SERVICE_GB2312_FONT_HEI=y
CONFIG_FONT_SERVICE_ENABLE_BUILTIN=y
```

### 5.1 显示容量与滚动

128×64 屏每行 8 个 16×16 字，一屏 4 行 = **32 个汉字**。AI 回答通常远超此长度，
**必须实现滚动显示**。

### 5.2 待解决：分区容量

当前 `sdkconfig` 使用 `CONFIG_PARTITION_TABLE_SINGLE_APP=y`，
app 分区仅 `0x100000`（1 MB），现有固件 237 KB。加入 752 KB 字库后约 989 KB，**会溢出**。

处理方案（三选一，待定）：

| 方案 | 说明 |
| --- | --- |
| A. 换自定义分区表，扩 app 分区 | 需确认模块实际 Flash 容量 |
| B. 字库挪到 W25Q128 外部 Flash | `FONT_TYPE_W25Q` 已预留但**未实现**，需开发 |
| C. 字库裁剪为更小子集 | 需评估覆盖度，AI 回答用字不可预知，风险高 |

> **建议**：优先方案 A（扩分区）。方案 B 虽然优雅但 `FONT_TYPE_W25Q` 尚未实现，
> 工作量不小于 A；方案 C 覆盖面不可控。

## 六、AI 对话模式

### 6.1 唤醒与对话流程

WiFi 连接成功后进入 AI 待机模式，通过 ESP-SR 离线唤醒检测「小乐同学」，
唤醒后语音提示「我在」并进入对话状态。

```
语音输入 → STT 转文本 → 发送 AI API → 接收回答 → TTS 播报 + 0.96" 屏滚动显示
```

对话超时（如 30 秒无输入）自动退回待机重新等待唤醒。

### 6.2 AI 平台对接（天翼云 EAI）

| 配置项 | 值 |
| --- | --- |
| Base URL | `https://eaichat.ctyun.cn/ai/platform/v2/cp` |
| 模型 model | `glm-5.3-oc` |
| 协议类型 | `openai-completions` |
| 鉴权方式 | HTTP Header: `Authorization: Bearer <API_KEY>` |
| API Key | **见 6.5 安全要求，不在本文档中明文记录** |

请求示例：

```
POST https://eaichat.ctyun.cn/ai/platform/v2/cp/chat/completions
Authorization: Bearer <API_KEY>
Content-Type: application/json

{
  "model": "glm-5.3-oc",
  "messages": [
    {"role": "system", "content": "你是智能语音助手小乐"},
    {"role": "user",   "content": "今天天气怎么样"}
  ],
  "stream": false
}
```

> 具体 path（是否带 `/chat/completions` 后缀）以平台文档实际为准，
> 先用 curl/Postman 跑通再写进固件。

### 6.3 上下文与异常处理

- 维护滑动窗口上下文，保留最近 **6~10 轮**，控制 token 与延迟
- HTTP 超时 **10~15 秒**，重试 **1 次**
- 失败时播报「网络异常，请重试」并在 OLED 提示
- 区分「网络不通」与「API 返回错误」分别反馈

### 6.4 语音链路方案（v3.0 明确的三层分工）

| 环节 | 方案 | 理由 |
| --- | --- | --- |
| 唤醒词 | **ESP-SR 离线** | 文档要求「小乐同学」本地唤醒、延迟 ≤1 秒，在线无法达成该指标 |
| STT | **在线 ASR** | ESP32-S3 本地识别准确率不足，且吃满 CPU |
| TTS | **在线接口** | 天翼云 EAI 仅处理文本问答，不提供 TTS，需另选供应商 |

### 6.5 API Key 安全要求

- API Key **必须烧录时一次性写入 NVS（建议加密分区）**，运行时读取拼装 Header
- **严禁**明文硬编码进固件
- **严禁**写入可被 U 盘读出的日志文件
- **严禁**提交进代码仓库或本需求文档

> **警告**：v2.1 文档中曾明文列出 API Key，且该 Key 已在开发过程中被查看过，
> **建议在平台侧立即轮换**后再继续开发。

## 七、存储与 USB 文件访问

### 7.1 W25Q128 双分区

W25Q128 为 SPI NOR Flash，无内部 FTL，**不直接挂 FATFS 当裸盘**。采用双分区：

| 分区 | 大小 | 用途 |
| --- | --- | --- |
| LittleFS 日志分区 | 约 10~12MB | 日常存对话记录，按天写入 |
| FAT32 导出分区 | 约 2~4MB | USB 插电脑时供 PC 只读/读写 |
| 预留 | 约 1~2MB | 中文字库、配网资源、OTA |

### 7.2 日志格式

按天切分文件，如 `/logs/2026-10-03.csv` 或 `.jsonl`，每行一条记录；单条限长 ≤ 2KB。

```json
{"time":"2026-10-03 10:00:00","role":"user","text":"今天天气怎么样"}
{"time":"2026-10-03 10:00:05","role":"ai","text":"上海今天多云，气温..."}
```

写满时删除最旧的按天日志文件（循环覆盖），并语音提示「存储空间已满，已覆盖最旧记录」。
LittleFS 建议启用 lookahead 与 `block_cycles`（约 512）做磨损均衡。

### 7.3 USB 文件访问流程

1. 检测 USB 插入或按键触发，进入 USB 导出模式
2. 暂停 AI 对话、STT/TTS 及 WiFi 数据写入
3. 将近期日志从 LittleFS 分区复制到 FAT32 导出分区
4. 通过 TinyUSB MSC 把 FAT32 分区注册为 U 盘
5. 电脑文件管理器出现可移动磁盘，直接读取日志文件
6. 拔出 USB 后退出 MSC 模式，恢复正常运行

### 7.4 实现要点

- **严禁 PC 与 MCU 同时写同一份数据**，导出期间必须暂停 AI 日志写入，否则 FAT 分区易损坏
- 若仅需查看，可将 FAT32 分区做成**只读**更安全
- 若需 PC 写入配置，拔出时做一致性检查
- 日志文件用 `.txt`/`.csv` 便于双击打开

### 7.5 组件选型

| 需求 | 选型 | 类型 |
| --- | --- | --- |
| 裸 SPI 读写 | `main/w25q128.c`（本项目） | 已实现 |
| FATFS 挂载 | 官方 `fatfs` 组件 | 官方 |
| LittleFS 挂载 | 官方 `littlefs` 组件 | 官方 |
| 完整 W25Qxx 驱动 | `d:\components\w25qxx_driver` | 自定义 |

> `main/w25q128.c` 只做裸 SPI 层。**一旦需要 LittleFS / FAT32 / 分区表 / USB MSC，
> 必须改用 `w25qxx_driver` + 官方组件，不要继续扩本文件。**

## 八、电源管理

3.7V 锂电池 → TP4056/TP4057 充电管理 → 电池保护（DW01+8205A）→ 升压/稳压至 3.3V，
ESP32-S3 通过电阻分压 ADC 采样检测电量。

| 状态 | 处理 |
| --- | --- |
| 电压 < 3.3V | 语音提示「电量不足」 |
| 电压 < 3.0V | 关闭 WiFi/AI，保留基础显示或关机保护 |
| 充电中 | OLED 显示「正在充电」 |

## 异常处理

- API 调用失败区分「网络不通」与「API 返回错误」分别反馈
- Flash 写入异常时跳过本次记录，不影响主流程
- 上电自动从 NVS 读取 WiFi 配置进入对应状态
